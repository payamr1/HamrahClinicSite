# همراه کلینیک — نسخه‌ی جدید

بازنویسی کامل hamrahclinic.ir با PHP خام و MySQL، بدون وردپرس.

**قاعده‌ی حاکم بر کل پروژه:** هر ۸۲ آدرس ایندکس‌شده‌ی سایت فعلی باید در
نسخه‌ی جدید کد ۲۰۰ برگردانند. فهرست مرجع در `current-urls-82.txt` است و
هر مسیری که کد ۲۰۰ نگیرد، یک خطای انتشار محسوب می‌شود.

---

## ساختار

```
public/          ریشه‌ی وب — تنها پوشه‌ای که از مرورگر دیده می‌شود
app/             کد برنامه: Router، Database، Seo، Repository، قالب‌ها
db/              schema.sql و داده‌ی اولیه
admin/           پنل مدیریت
seo/             متای بازنویسی‌شده‌ی ۸۲ صفحه + صفحه‌ی بازبینی
design/          ماکاپ‌های تأییدشده و توکن‌های رنگ
```

روی سرور، کد برنامه بیرون از ریشه‌ی وب قرار می‌گیرد:

```
~/public_html/             ← محتوای public/
~/hamrah-app/app/          ← کد
~/hamrah-app/db/           ← اسکیما و seed
~/hamrah-app/config.php    ← رمز دیتابیس (در مخزن نیست)
```

---

## استقرار — بار اول

### ۱. مخزن را روی گیت‌هاب بگذارید

روی گیت‌هاب یک مخزن **خصوصی** بسازید، بعد در ترمینال همین پوشه:

```bash
git remote add origin https://github.com/USER/hamrah-clinic.git
git push -u origin main
```

### ۲. دیتابیس بسازید

cPanel ▸ **MySQL Databases** ▸ یک دیتابیس و یک کاربر بسازید و کاربر را با
دسترسی `ALL PRIVILEGES` به دیتابیس وصل کنید. نام و رمز را نگه دارید.

### ۳. مخزن را در cPanel وصل کنید

cPanel ▸ **Git Version Control** ▸ Create:

| فیلد | مقدار |
|---|---|
| Clone URL | آدرس مخزن گیت‌هاب |
| Repository Path | `repositories/hamrah-clinic` |
| Repository Name | `hamrah-clinic` |

بعد از ساخته شدن، تب **Pull or Deploy** ▸ دکمه‌ی **Update from Remote** و
سپس **Deploy HEAD Commit**.

> اگر clone انجام نشد، احتمالاً سرور به گیت‌هاب دسترسی ندارد. در آن صورت
> `git bundle` یا آپلود zip از File Manager جایگزین است — خبر بدهید.

### ۴. مسیر ریشه‌ی وب را چک کنید

cPanel ▸ **Domains** ▸ روی `new.hamrahclinic.ir` ▸ مقدار Document Root.
ریشه‌ی وب این اکانت `/public_html` است و در `.cpanel.yml` تنظیم شده. اگر عوض شد، فقط خط `WEBROOT`
را عوض کنید و دوباره deploy بزنید.

### ۵. config.php را پر کنید

File Manager ▸ پوشه‌ی `hamrah-app` ▸ فایل `config.php.example` را به
`config.php` تغییر نام دهید و ویرایش کنید:

- `db.name` و `db.user` و `db.pass` ← از مرحله‌ی ۲
- `app_key` ← یک رشته‌ی تصادفی؛ در Terminal: `php -r "echo bin2hex(random_bytes(32));"`

سه مقدار زیر را **دست نزنید** تا روز جایگزینی:

```php
'env'            => 'staging',
'force_noindex'  => true,
'canonical_host' => 'hamrahclinic.ir',
```

### ۶. جدول‌ها را بسازید

cPanel ▸ **phpMyAdmin** ▸ دیتابیس را انتخاب کنید ▸ تب Import، **به همین ترتیب**:

1. `db/schema.sql` — ساخت ۱۳ جدول
2. `db/seed/01-pages.sql` — ۸۲ آدرس با متای سئو
3. `db/seed/02-clinics-doctors.sql` — ۹ کلینیک، ۱۲ پزشک و اتصال‌ها
4. `db/seed/03-content.sql` — متن صفحات، استخراج‌شده از سایت فعلی
5. `db/seed/04-faqs.sql` — ۱۲۹ سؤال متداول روی ۳۹ صفحه (منبع FAQPage)

یا فقط `db/install.sql` که هر پنج فایل را یک‌جا دارد.

ترتیب مهم است: فایل سوم با `path` به صفحات فایل دوم وصل می‌شود.

> اگر import با خطای **۱۲۱ (Duplicate key)** شکست خورد، یعنی جدول‌ها از
> قبل وجود دارند. اول `db/reset.sql` را import کنید تا همه‌چیز پاک شود،
> بعد `db/install.sql`. چیزی از دست نمی‌رود.

### ۷. سلامت را بررسی کنید

```
https://new.hamrahclinic.ir/_health.php
```

باید همه‌ی ردیف‌ها «قبول» باشند و «آدرس‌های ثبت‌شده» عدد **۸۲ از ۸۲** را
نشان دهد.

### ۸. گواهی SSL

cPanel ▸ **SSL/TLS Status** ▸ `new.hamrahclinic.ir` را تیک بزنید ▸
**Run AutoSSL**.

## محافظت سئویی

سه لایه جلوی ایندکس شدن نسخه‌ی آزمایشی را می‌گیرند. تا روز جایگزینی
هیچ‌کدام را خاموش نکنید:

1. هدر `X-Robots-Tag: noindex` در `public/.htaccess`
2. `force_noindex => true` در `config.php`
3. تگ `canonical` که به `hamrahclinic.ir` اشاره می‌کند، نه به `new.`

اگر نسخه‌ی آزمایشی ایندکس شود، با سایت اصلی محتوای تکراری می‌سازد و به
رتبه‌ی هر دو آسیب می‌زند.

---

## روز جایگزینی

1. کل دیتابیس و فایل‌ها را برای رشته‌ی `new.hamrahclinic.ir` جست‌وجو و پاک‌سازی کنید
2. در `config.php`: `env => 'production'` و `force_noindex => false`
3. بلوک `X-Robots-Tag` را از `.htaccess` حذف کنید
4. `public/_health.php` را حذف کنید
5. هر ۸۲ آدرس `current-urls-82.txt` را تست کنید — همه باید ۲۰۰ بدهند
6. سایت‌مپ را در سرچ کنسول دوباره ثبت کنید
7. سی روز گزارش Page Indexing و Core Web Vitals را هفتگی ببینید

## توسعه‌ی محلی

روی این کامپیوتر PHP نصب نیست، پس تست روی `new.hamrahclinic.ir` انجام
می‌شود. برای اجرای محلی:

```bash
php -S localhost:8000 -t public
```

و در `config.php` مقدار `db.host` را به دیتابیس محلی وصل کنید.

بازتولید داده‌ی اولیه از فایل متا:

```bash
perl db/seed/gen-pages.pl
```

## پنل مدیریت

نشانی: `https://new.hamrahclinic.ir/admin/`

ورود **فقط با کد یک‌بارمصرف پیامکی** است. رمز عبوری در کار نیست.

### پیش از هر چیز: کاوه‌نگار

بدون این تنظیم هیچ‌کس نمی‌تواند وارد پنل شود. در
`~/hamrah-app/config.php` بخش `sms` را پر کنید:

```php
'sms' => [
    'api_key'  => 'کلید وب‌سرویس',
    'sender'   => '100020000',      // شماره‌ی خط شما
    'message'  => '',               // خالی = متن پیش‌فرض
    'template' => '',
    'emergency_log_code' => false,
],
```

| مقدار | از کجا |
|---|---|
| `api_key` | کاوه‌نگار ◂ حساب کاربری ◂ **انتخاب وب سرویس** |
| `sender` | شماره‌ی خط خودتان، دقیقاً همان‌طور که در پنل کاوه‌نگار نوشته شده |

**⚠ خط تبلیغاتی برای کد ورود مناسب نیست.** خیلی از کاربران پیامک
تبلیغاتی را روی خط خودشان بسته‌اند (لیست سیاه تبلیغاتی اپراتور) و
در آن صورت کد هرگز نمی‌رسد — نه خطایی می‌بینید نه پیامکی. اگر
خطتان خدماتی نیست، **پیش از ساخت حساب** یک بار از پنل کاوه‌نگار به
موبایل خودتان پیامک بفرستید و مطمئن شوید می‌رسد.

#### متن پیامک

`message` را خالی بگذارید تا این متن برود:

```
کد ورود پنل همراه کلینیک: 123456
تا ۳ دقیقه معتبر است.
```

اگر خواستید عوضش کنید، `{code}` جای کد می‌نشیند. حواستان به طول
باشد: **پیامک فارسی هر صفحه ۷۰ نویسه است** و یک نویسه بیشتر یعنی
دو برابر هزینه در هر بار ورود. `_health.php` طول و تعداد صفحه‌ی
متن فعلی را نشان می‌دهد.

`https://new.hamrahclinic.ir/_health.php` وضعیت همین تنظیمات را
گزارش می‌دهد — پیش از ساخت حساب یک بار نگاهش کنید.

### ساخت حساب

بار اول که `/admin/` را باز کنید صفحه‌ی **ساخت حساب مدیر** می‌آید.
نام و شماره‌ی موبایل را وارد می‌کنید و همان شماره از آن پس تنها راه
ورود است. بعد از ساخت اولین حساب، آن صفحه خودبه‌خود بسته می‌شود.

شماره‌ها عمداً در مخزن نیستند — این مخزن عمومی است و شماره‌ی شخصی
جایش اینجا نیست. مدیرهای بعدی را از داخل پنل (▸ حساب من) اضافه
می‌کنید.

### سقف‌ها

| | |
|---|---|
| عمر کد | ۳ دقیقه |
| تلاش برای هر کد | ۵ بار، بعد ۱۵ دقیقه قفل |
| فاصله‌ی دو ارسال | ۹۰ ثانیه |
| سقف ارسال در ساعت | ۶ بار |

کد هرگز ذخیره نمی‌شود، فقط هشش. شماره‌ای که در فهرست مدیران نباشد
هیچ پیامکی نمی‌گیرد ولی همان پاسخ را می‌بیند — وگرنه هر کسی
می‌توانست بفهمد کدام شماره مدیر است، و با شماره‌ی دلخواه برای شما
خرج پیامک بتراشد.

### اگر پیامک نرسید

اول `_health.php` و اعتبار حساب کاوه‌نگار را ببینید. اگر کاوه‌نگار
از دسترس خارج شده و باید همین حالا وارد شوید، در `config.php`:

```php
'emergency_log_code' => true,
```

از این پس کد به‌جای پیامک در لاگ خطای PHP نوشته می‌شود و از File
Manager قابل خواندن است. **این امنیت را کم می‌کند** — هر کسی که به
فایل‌های سرور دسترسی دارد کد را می‌بیند. تا وقتی روشن است پنل یک
نوار هشدار زرد نشان می‌دهد. بعد از ورود فوراً `false` کنید.

### کتابخانه‌ی رسانه

هر فایلی که بالا می‌رود — عکس یا ویدیو — می‌تواند هم‌زمان چند
«تگ» بگیرد، و برای هر تگ جداگانه مشخص می‌شود که نقشش چیست:

| نقش | یعنی چه |
|---|---|
| **پروفایل** | روی کارت آن پزشک/بخش در فهرست‌ها دیده می‌شود |
| **گالری** | در گالری همان پزشک/بخش/خدمت می‌نشیند |

اگر یک نفر یا یک بخش **چند عکس پروفایل** داشته باشد، عکس‌ها در
فهرست‌ها نوبتی عوض می‌شوند. این کار کاملاً با CSS انجام می‌شود؛
اگر کاربر در سیستم‌عاملش «کاهش حرکت» را روشن کرده باشد، چرخش
متوقف می‌شود و فقط عکس اول می‌ماند.

تگ «**گالری عمومی کلینیک**» فایل را به صفحه‌ی `/گالری/` می‌فرستد.
آنجا بازدیدکننده می‌تواند بر اساس نوع (عکس/ویدیو) و بر اساس هر
پزشک یا بخش فیلتر کند. فیلترها با query string کار می‌کنند، پس هر
نما آدرس خودش را دارد و `canonical` همه به آدرس تمیز گالری اشاره
می‌کند تا محتوای تکراری ساخته نشود.

### عکس‌ها خودشان آماده می‌شوند

فایل خام ذخیره نمی‌شود. هر عکسی که بالا می‌رود پیش از ذخیره سه کار
رویش انجام می‌شود:

1. **چرخش اصلاح می‌شود** — عکس موبایل معمولاً افقی ذخیره می‌شود و
   زاویه‌اش در EXIF می‌نشیند. چون بازنویسی EXIF را پاک می‌کند، اگر
   اول نچرخانیمش عکس تا ابد کج می‌ماند.
2. **کوچک می‌شود** تا بلندترین ضلع حداکثر ۲۴۰۰ پیکسل. بزرگ‌تر از
   این در هیچ قاب سایت دیده نمی‌شود. عکس کوچک‌تر بزرگ نمی‌شود.
3. **دوباره فشرده می‌شود** و EXIF می‌افتد. این دومی فقط حجم نیست:
   عکس موبایل **مختصات جغرافیایی** با خودش دارد و آن نباید روی
   سایت عمومی منتشر شود.

چند تصمیم ریز که فرق می‌کنند:

- PNG فقط وقتی PNG می‌ماند که واقعاً شفافیت داشته باشد. عکس معمولیِ
  ذخیره‌شده در PNG چند برابر همان در JPEG وزن دارد، پس به JPEG
  تبدیل می‌شود.
- اگر نتیجه از فایل اصلی بزرگ‌تر شد و کوچک‌کردنی هم لازم نبود، همان
  اصلی نگه داشته می‌شود — عکسی که از قبل بهینه است نباید با
  بازفشرده‌سازی بدتر شود.
- پیش از باز کردن عکس، حافظه‌ی باقی‌مانده سنجیده می‌شود. GD هر
  پیکسل را ۴ بایت نگه می‌دارد؛ بدون این بررسی یک عکس بزرگ به‌جای
  پیام خطا کل درخواست را می‌کشد.
- اگر GD نبود یا پردازش شکست خورد، فایل اصلی ذخیره می‌شود تا
  بارگذاری بی‌صدا از دست نرود.

این جدا از نسخه‌های کوچکِ در لحظه است: آن‌ها همچنان از همین فایل
ساخته و در `assets/cache/img/` کش می‌شوند.

### ویدیو


دو راه دارد:

- **بارگذاری فایل** — MP4 یا WebM تا ۱۲۸ مگابایت
- **نشانی آپارات یا یوتیوب** — بهتر است برای ویدیوی بلند

ویدیوی آپارات و یوتیوب تا وقتی بازدیدکننده کلیک نکند بارگذاری
نمی‌شود. `iframe` این سرویس‌ها به‌تنهایی از کل صفحه‌ی ما سنگین‌تر
است و کوکی شخص ثالث هم می‌آورد.

### امنیت بارگذاری

سه لایه روی هم:

1. نوع واقعی فایل از محتوایش خوانده می‌شود (`getimagesize` و
   `finfo`)، نه از پسوند
2. نام فایل از نو ساخته می‌شود و ورودی کاربر هرگز وارد مسیر نمی‌شود
3. `public/assets/uploads/.htaccess` اجرای هر اسکریپتی را در آن
   پوشه می‌بندد

پوشه‌ی `uploads` در مخزن نیست — فقط `.htaccess`اش هست. فایل‌های
بارگذاری‌شده روی سرور می‌مانند و `.cpanel.yml` چیزی را در آن پاک
نمی‌کند.

### بررسی ساختاری کد

روی این ماشین PHP نصب نیست، پس به‌جای `php -l`:

```bash
perl db/php-structure-check.pl
```

پرانتز و آکولاد بازمانده، رشته‌ی بسته‌نشده، heredoc ناتمام و فاصله‌ی
اضافه بعد از `?>` را می‌گیرد. جایگزین کامل کامپایلر نیست.
